#58 viewer のパスワードの変更が share に自動で反映される

変更前 → 変更後。caddy は Secret share-grafana を起動時に 1 度だけ環境変数で読んでいたので、viewer のパスワードを変えると deploy/grafana と deploy/share の両方を rollout restart するまで Grafana の経路が 302 になり、share を作り直すと Quick Tunnel の URL も変わった。auth が実行時に Secret を読んで Basic を組み、caddy はそれを Grafana への Authorization にする。再起動は要らず、URL は変わらない (Closes #58)。

1. 何が変わるか

項目変更前変更後
根本原因Basic の値 (base64("viewer:<パスワード>")) を caddy の起動スクリプトが 1 度だけ組み、環境変数 SHARE_GRAFANA_BASIC として持つ。環境変数は起動時にしか読まれず、just up は開いている Pod を作り直さないので、Secret を書き換えても caddy の値は古いまま
Basic を組む場所caddy の起動スクリプト (entrypoint.sh)。起動時に 1 度auth (share_auth.py)。Secret share-grafana を API で読み (最大 2 秒の覚え)、X-Share-Grafana-Authorization として応答に載せる
パスワードを変えたあとdeploy/grafana と deploy/share の両方を rollout restart。片方だけだと Grafana の経路が 302deploy/grafana だけ (DB へそろえる)。share は再起動しない。次に読み直した要求から新しい値が渡る
Quick Tunnel の URLshare を作り直すので変わる (配った URL が使えなくなる)変わらない (Pod を作り直さない)
share-grafana が無い・空caddy が Caddyfile.closed で起動し、3 経路すべて 503Grafana の経路だけ 503 (認証が通らなければ 401 のまま)。headroom・backstage は動く。鍵が付かない応答は caddy も 503
人の Authorizationcaddy が header_up で差し替え同じく差し替え。複数本付けても全部置き換わり、偽の X-Share-Grafana-Authorization は先に消す。試験で固定
RBACshare-credentials・share-session-key の get+ share-grafana の get だけ。list・watch は足さない
caddy の Secret 参照share-host と share-grafanashare-host だけ。require_env と Caddyfile.closed の選び方 (SHARE_RELAY_* が揃うか) は残す

4. 試験で固定すること (実クラスタは使わない)

完了条件試験
パスワードを変えると、再起動せずに新しい値が渡るtest_share_caddy.py test_viewer_value_change_reaches_grafana_from_the_next_request: 実物の caddy と認証サービスを立てたまま、share-grafana の写しを書き換え、Basic でも cookie でも次の要求から新しい鍵が Grafana の upstream に届く。API 版は test_share_auth.py の KubernetesSource (ttl の後に新しい値・消したら古い値を使い回さない)
share-grafana が無い・空のとき Grafana の経路は拒否test_grafana_is_denied_while_the_viewer_value_is_missing_or_empty: 許可リストの内も外も 503・upstream に届かない・認証なしは 401・headroom と backstage は 200。揃えると次の要求から通る。test_caddy_denies_grafana_when_the_auth_answer_has_no_key: 認証サービスが鍵を付けない代役でも caddy が 503
人が送った Authorization が Grafana に届かないtest_a_persons_credentials_never_reach_grafana: Basic・Bearer・小文字の名前・同名を複数本・Cookie・Proxy-Authorization・偽の X-Share-Grafana-Authorization を付けても、upstream が受けた資格情報のヘッダは viewer の Basic の 1 本だけ。test_a_forged_key_header_does_not_open_grafana_while_the_viewer_value_is_missing: 鍵が付けられないとき、偽の鍵のヘッダは通らない
viewer の鍵が Grafana 以外に漏れないtest_the_viewer_key_goes_only_to_grafana: headroom の中継・backstage の upstream に鍵のヘッダも viewer の Basic も届かない
RBAC は get だけ・caddy は share-grafana を参照しないtest_share_manifest.py: Role の rules を完全一致 (3 つの resourceNames・verbs: [get])。caddy の環境・Caddyfile・起動スクリプトに GRAFANA_VIEWER_PASSWORD・SHARE_GRAFANA_BASIC が無い
