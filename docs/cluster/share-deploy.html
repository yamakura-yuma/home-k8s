1. 公開の本体が、ホストのプロセスからクラスタ内の Pod になる

変更前は just share <対象> を打つ間だけ、ホストで cloudflared と caddy が動く。変更後は just up で Pod share が立ち、クラスタが立っている間は公開が開いている。 この Issue では資格情報が空なので、設計上はどの経路も 401 になる (下の流れは設計どおりの動きで、稼働中のクラスタでは未確認)。

2. just up の順序: Secret を、ArgoCD が Pod を作る前に置く

Pod は Secret が無いと起動できない (optional: false)。_share-secrets を root.yaml の apply (ArgoCD の同期) より前に打つ。

_kind-up→ _backstage-image→ _argocd-install→ _grafana-secrets→ _share-relay-up→ + _share-secrets→ _headlamp-token→ apply root.yaml→ + ArgoCD が share を同期
_grafana-secrets が viewer のパスワードのファイルを作り、_share-secrets がそれを namespace share の Secret share-grafana に写す (Secret は別 namespace の Pod から読めない)。share-credentials・share-session-key は、あれば何もしない (打ち直しで人の資格情報と cookie の鍵を消さない)。

3. Secret を作る処理すべてで、注釈に値が残らない (#49)

kubectl apply は Secret の中身を注釈 last-applied-configuration にも書く。replace・create に替える。

入れ方


    

    

      
kubectl get secret share-host -o yaml



    

  

  

    対象: share-relay.sh (share-host)・grafana-secrets.sh (grafana-admin・grafana-viewer・grafana-backstage・backstage-grafana)・新しい share-secrets.sh。
    入れ方は just/secret-lib.sh の put_secret (あれば replace、無ければ create)。replace は metadata を置き換えるので、以前の apply が残した注釈も消える。
    replace --force は動いている Pod の下で Secret を消すので使わない。headlamp-token.sh は data の無い Secret なので注釈に値が残らず、対象にしない。
