5. PBKDF2 化の diff (CodeQL py/weak-sensitive-data-hashing への手直し)

変更前は sha256(パスワード) を保存して比べていた。変更後は、項目ごとのソルトを付けた PBKDF2-HMAC-SHA256 (600,000 回、OWASP の推奨値) で保存し、照合に成功した結果だけを 30 秒覚えて、要求のたびに約 70ms を使わないようにする。

要求 (上の点は覚えがあるとき、下の点は外れたとき)

この手直しのファイル別 diff

ファイル変更前変更後
share_auth.py の保存形式hash = sha256 の hex 64 桁hash = pbkdf2_sha256$600000$<salt 32 桁>$<鍵 64 桁>。100,000 回未満・形の違うもの・旧形式は項目ごと拒否
share_auth.py の照合compare_digest(sha256(pw), hash)verify_password() (PBKDF2 → compare_digest)。名前が無いときもダミーで同じ反復を計算。VerifyCache が成功だけ覚える
share_auth.py の cookie 署名HMAC(鍵, 名前:保存 hash)HMAC(鍵, 名前:salt)。MAC であってパスワードのハッシュ化ではない。パスワードの派生物を入れず、salt (作り直すたびに変わる) だけに束ねる。作り直し後に古い cookie が効かない性質は同じ
share_auth.py の cookie名前をそのまま Set-Cookie に入れるurllib.parse.quote を通す (名前は [a-z0-9-] なので値は変わらない。CodeQL の response splitting 指摘への対応)
