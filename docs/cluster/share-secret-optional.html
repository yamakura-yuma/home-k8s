#64 Secret が無くても share Pod が起動する

変更前 → 変更後。Secret は just up の _share-secrets まで作られず、main のマージで同期された Pod は CreateContainerConfigError で止まっていた。参照を optional にして 全拒否で起動し、Secret ができたら読ませる (Closes #64)。

1. 何が変わるか

項目変更前変更後
根本原因Pod の Secret 参照が必須 (optional: false) なのに、Secret を作るのは ArgoCD の同期と別の手順 (just up)。同期が先になる既存のクラスタでは、Secret が無く kubelet が Pod を始められない
Secret が 1 つも無いときCreateContainerConfigError のまま止まる (study-kind で 3 時間)Pod は Running。3 つの経路すべて 503 (caddy)、auth は全部 401。素通し・認証抜けにならない
caddy の起動sh -c の中で Basic を組み立てて caddy runentrypoint.sh が 3 つの値 (SHARE_RELAY_ADDR・SHARE_RELAY_TOKEN・viewer のパスワード) のどれか 1 つでも無い・空なら全拒否の Caddyfile.closed、揃えば Caddyfile
require_env必須の値が空だと caddy が起動しない (番人)そのまま残す。スクリプトが空を先に見分けて Caddyfile.closed を選ぶので、空の Caddyfile を渡して落ち続けることもない。base64("viewer:") は空でないので、パスワードの空は組み立てる前に見る
Secret ができたあと(Pod が起動できないので、Secret を作ると kubelet の再試行で起動)auth: 次に読み直した要求 (最大 2 秒) から効く。caddy: 環境変数は起動時にしか読まれないので、just up の最後の段が閉じて起動した Pod だけを作り直す
2 回目以降の just upPod に触れないPod に触れない (caddy のログに「全経路を 503 で拒否」が無い)。Quick Tunnel の URL は変わらない
#58 との関係Grafana の Basic を auth が実行時に組む形になれば、起動スクリプトと Caddyfile から viewer のパスワードと SHARE_GRAFANA_BASIC を外すだけ。require_env と Caddyfile.closed の選び方 (SHARE_RELAY_* が揃うか) は残るので衝突しない

4. 試験で固定すること (実クラスタは使わない)

完了条件試験
Secret が 1 つも無くても CreateContainerConfigError にならないtest_share_manifest.py: Pod の Secret 参照 (env・envFrom・volume) すべて optional: true。init コンテナで Secret を待たない
3 つの経路がすべて拒否test_share_caddy.py ShareCaddyEntrypoint: Deployment と同じ entrypoint.sh から実物の caddy を、環境変数が無い・空・1 つ欠ける状態で立て、3 ポート × 許可リストの内外 × (認証なし・正しい Basic・偽の cookie・Bearer) が全部 503、upstream に届かない
Secret ができたあと正しく動く揃えて立て直すと認証なし 401・許可リストの内 200・外 404・Grafana に viewer の鍵 (同じ entrypoint.sh)。auth は Secret が後からできると再起動なしで 200 (test_share_auth.py)
2 回目以降で Pod を作り直さないtest_share_secrets.py ShareSecretsRecreatePod: 閉じた Pod だけ消す。開いている Pod・Pod が無い・share-host が無いときは何も消さない。Deployment・rollout・--force に触れない
